## Part 1: The Core Languages (The Holy Trinity of the Web)

Everything on this site, even though it is generated by a tool (Eleventy), eventually boils down to three languages that your browser understands.

### 1. HTML5 (HyperText Markup Language)
**What it does:** It creates the skeleton and content of the page.
**Where to find it:** Inside `.html` files (like `src/history.html`) and inside `.njk` files (Nunjucks templates).
**How it's used here:**
Look at `src/_includes/base.njk` line 1-3:
```html
<!DOCTYPE html>
<html lang="en">
<head>
```
- `<!DOCTYPE html>` tells the browser "this is a modern HTML5 document".
- `<html>` is the root element.
- `<head>` contains invisible metadata (like SEO titles and links to CSS).
- `<body>` contains the visible content.

### 2. CSS3 (Cascading Style Sheets)
**What it does:** It makes the HTML look beautiful (colors, layout, spacing).
**Where to find it:** `src/css/style.css`, `src/css/mobile-fix-v2.css`, and `src/css/tools-v2.css`.
**How it's used here (Advanced CSS Variables):**
Instead of hardcoding colors, this site uses variables. In `src/index.njk` line 13, you can see this:
```css
:root { 
  --hp-bg: #f6f5f0; 
  --hp-text: #2c2418; 
  --hp-accent: #8b6914; 
}
[data-theme="dark"] { 
  --hp-bg: #1a1714; 
  --hp-text: #f0ebe2; 
}
```
- `:root` means these variables apply to the whole HTML document.
- `[data-theme="dark"]` means "if the user turns on dark mode, swap the variables to these dark colors."
- Later in the CSS, it says `background: var(--hp-bg);`. This is how the site can instantly switch between light and dark modes!

### 3. JavaScript (Vanilla JS)
**What it does:** It adds logic, memory, and interactivity. 
**Where to find it:** `src/js/app.js`, `src/js/pdf-editor.js`, and directly inside `<script>` tags on some pages.
**How it's used here (DOM & LocalStorage):**
JavaScript talks to the HTML using the **DOM (Document Object Model)**.
- **Example - The History Feature:** When you use a tool, JavaScript grabs that tool's name and saves it using `window.localStorage.setItem('recent_tools', tool_data)`. `localStorage` is a database built right into your browser. When you go to `history.html`, JavaScript reads that data using `window.localStorage.getItem('recent_tools')` and dynamically writes HTML to the page to show your history, all without needing a backend server!

## Part 2: The Architecture - Eleventy (11ty)

Writing raw HTML for every single page is exhausting. If you want to change the footer link, you'd have to edit 30+ files! 

To fix this, the site uses **Eleventy (11ty)**, a Static Site Generator. It runs on **Node.js** (a program that lets JavaScript run on your computer, not just in the browser).

### How Eleventy Works
1. You write a "Template" (like `src/_includes/partials/footer.njk`).
2. You write a "Page" (like `src/index.njk`).
3. You run a build command (`npm run build`).
4. Eleventy reads all your files, squishes them together according to your instructions, and spits out finished `.html` files into a hidden folder (usually `_site`).

### Nunjucks (`.njk`) - The Templating Language
Nunjucks looks like HTML, but it has "superpowers" wrapped in `{% %}` and `{{ }}`.

**Superpower 1: Includes (Injecting Code)**
In `src/_includes/base.njk` (Line 18):
```njk
{% include "partials/header.njk" %}
```
This tells Eleventy: "Go find the header file, copy all its code, and paste it exactly right here."

**Superpower 2: Extends and Blocks (The Skeleton)**
Look at the top of `src/index.njk`:
```njk
{% extends "base.njk" %}
{% block head %}
  <style> ... </style>
{% endblock %}
```
This tells Eleventy: "I want to use the `base.njk` skeleton. Wherever `base.njk` has a placeholder called `{% block head %}`, put this `<style>` tag there."

**Superpower 3: Variables (Front Matter)**
At the very top of `src/index.njk`, you see YAML data between `---` dashes:
```yaml
---
title: OnlinePDFPro - PDF Tools
---
```
This is called **Front Matter**. It creates variables for that specific page. In `base.njk` (Line 4), there is a meta partial that will use `{{ title }}` to generate the `<title>OnlinePDFPro - PDF Tools</title>` tag for the browser tab.

## Part 3: Deep Dive into the Codebase (Line by Line Examples)

### 1. The Content Security Policy (Security)
In `src/_includes/base.njk` Line 5, there is a massive `<meta http-equiv="Content-Security-Policy"...>` tag.
- This is a strict security guard. It tells the browser: "Only load scripts and styles from 'self' (this website), Google Fonts, and a few specific CDNs (like unpkg.com)." 
- If a hacker tries to inject a malicious script from a bad website, the browser will block it because it's not on this approved list.

### 2. The Service Worker (Offline Capabilities)
In `src/_includes/base.njk` Line 26:
```html
<script>if ('serviceWorker' in navigator) { navigator.serviceWorker.register('{{ '/sw.js' | url }}'); }</script>
```
- A Service Worker (`src/sw.js`) is a JavaScript file that runs in the background of the browser, separate from the web page. 
- It intercepts network requests. It can cache (save) images, CSS, and HTML so that if the user loses internet connection, the site still loads instantly!

### 3. Client-Side Tool Processing
This site handles PDF processing entirely in the user's browser, which is why the tagline is "privacy-first".
- It uses external libraries like `pdf-lib` and `pdfjs` (located in `src/js/`).
- When a user uploads a PDF, it doesn't get sent to a server. Instead, the local JavaScript reads the file into the computer's memory, uses mathematical functions to compress or edit it, and generates a new file blob for the user to download.

## Part 4: The Build and Deployment Pipeline

How does code go from your computer to the live internet?

### 1. The `package.json` file
This file tells Node.js what to do. Look at the `scripts` section:
```json
"scripts": {
  "build": "npx @11ty/eleventy",
  "dev": "npx @11ty/eleventy --serve",
  "sync:root": "node scripts/sync-to-root.js"
}
```

### 2. Local Development (`npm run dev`)
When you type `npm run dev` in your terminal:
1. `npx` tells Node to run Eleventy.
2. `--serve` tells Eleventy to start a local web server (usually at `http://localhost:8080`).
3. Whenever you save a file, Eleventy notices, rebuilds the site in 0.1 seconds, and automatically refreshes your browser.

### 3. Publishing (`npm run sync:root`)
Because this project is hosted on **GitHub Pages**, GitHub expects the final `index.html` file to be right in the main folder (the root).
But Eleventy builds into a hidden `_site/` folder.
So, the AI wrote a custom script: `scripts/sync-to-root.js`.
When you run `npm run sync:root`:
1. Node.js executes that JavaScript file.
2. The script copies every single `.html` file from the hidden `_site/` folder and pastes it directly into your main project folder.
3. You then commit those changes to Git (`git add .`, `git commit -m "update"`, `git push`).
4. GitHub sees the new `index.html` in the root and instantly updates the live website!
